Structural differences

  • A Workflow first — vertical staging: hero draft → send row → demoted session rail under a seam.
  • B Session Story — identity card + indigo rail; model/thinking live inside a prose sentence above a recessed stage.
  • C Docked Ops Band — single horizontal ops baseline (~74px); every control owns a fixed spatial slot for scanning and keyboard reach.

Judge rendered pixels and task flow, not titles. Lock is a candidate only until you confirm in chat.

A — Workflow first

Stage attention vertically: draft + send own the top of the card; workspace / model / thinking sit on a quiet seam-docked rail that never competes with Send.

Lead lens: Workflow and information hierarchy · skill://baseline-ui

Layout / interaction: Three tiers: (1) hero textarea, (2) action row with + left and primary Send right, (3) session meta rail below a seam. Pickers demoted; draft path is primary.

Tradeoffs
  • Gains: Clear attention staging; session state always visible but subordinate; single primary action.
  • Costs: Extra vertical row vs single footer; one more glance for meta.
  • Risks: Tall slash menu floats over transcript; rail can read as a second card if borders are wrong.
  • Rejected defaults: Chips + send in one competing footer row; ask options inside the box; Interrupt/Esc in composer.

B — The Session Story

A deliberate writing surface for steering the agent: indigo identity rail + caption, with model and thinking woven into a prose sentence — not a terminal prompt.

Lead lens: Product identity and narrative rhythm · skill://improve-ui

Layout / interaction: Card with 4px indigo rail. Caption “Follow-up to powder”. Sentence “Guiding with [model] at [thinking] reasoning”. Recessed writing stage. Action row is only + Commands and Send.

Tradeoffs
  • Gains: Session controls legible as prose; strong identity; calm primary action; airy rhythm.
  • Costs: ~15% more vertical chrome; sentence-selects hide conventional picker affordance; long model ids wrap.
  • Risks: May feel decorative to speed-first operators; caption assumes one workspace; native select popups stay OS-styled.
  • Rejected defaults: Dense chip toolbar; ask choices in composer; attach/permissions/Interrupt/Esc in composer; model/thinking in a separate sheet.

C — Docked Ops Band

One docked operations band: every control (workspace, model, thinking, slash, input, send) owns a stable spatial slot on one baseline for muscle memory and keyboard reach.

Lead lens: Dense operations and spatial scanning · skill://baseline-ui

Layout / interaction: Single horizontal band [workspace][model][thinking][+] [input] [Send] + 26px status/hint bar (~74px chrome). Popovers open upward. No stacked rails.

Tradeoffs
  • Gains: Lowest chrome; stable slots; keyboard-first lists with m/t hints; more transcript visible.
  • Costs: Toolbar-dense feel; less inviting for long narrative drafts; less room for helper text beside the box.
  • Risks: One row can over-stuff; keycap badges crowd on narrow widths; depends on header owning Interrupt/Esc.
  • Rejected defaults: Tall card above a control rail; attach/permissions cluster; ask-option strip in box; two-row band by default.
