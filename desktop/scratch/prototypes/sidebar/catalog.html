Structural differences

  • A Workflow — needs strip + collapsible workspace sections + two-line rows (title/cwd) + time column.
  • B Places — workspace place cards (rail, monogram, path); agents as narrative rows inside the card.
  • C Dense ops — sticky micro workspace labels + single-line tabular columns [status|title|cwd|age].

Judge rendered pixels. Browser lock is a candidate only — confirm in chat before production work.

A — Workflow hierarchy

Needs-you strip first, then workspace sections with a strict title / cwd / time grid so urgency and place both scan cleanly.

Lead lens: Workflow and information hierarchy

Layout / interaction: Collapsible workspace sections; two-line pane rows (title + mono cwd); sticky section headers; stable time column; elevated needs strip.

Tradeoffs
  • Gains: Urgency and workspace place both visible; strong vertical alignment; cwd always on-row.
  • Costs: Two-line rows use more height; needs strip can duplicate a row.
  • Risks: Collapsing sections may hide urgency if overused.
  • Rejected defaults: Flat attention list with no workspace grouping.

B — Place narrative

Each workspace is a place card (indigo rail, monogram, path); agents read as activity inside that place.

Lead lens: Product identity and narrative rhythm

Layout / interaction: Place header with monogram + ~/…path; agent cards with status pill; story line “In {basename} · last active”.

Tradeoffs
  • Gains: Memorable place identity; cwd anchored at workspace; calm selected state.
  • Costs: Fewest panes per viewport; more chrome per workspace.
  • Risks: Prose meta slower for power-user scanning.
  • Rejected defaults: Tabular single-line density.

C — Dense ops table

Tabular fixed columns under tight sticky workspace labels maximize scan rate and muscle memory.

Lead lens: Dense operations and spatial scanning

Layout / interaction: Column head Task/cwd/age; 28px rows; status icon slot; cwd basename column; arrow-key movement.

Tradeoffs
  • Gains: Most panes visible; stable spatial slots; keyboard friendly.
  • Costs: Least warmth; basename may collide across repos.
  • Risks: Over-dense for long titles.
  • Rejected defaults: Airy multi-line place cards.
